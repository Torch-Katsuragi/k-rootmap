# スキル作成ガイド

エージェントの機能を拡張するスキルを作成するためのガイド。

## スキルとは

スキルは、エージェントに専門的な知識やワークフロー、ツール統合を提供するモジュール式パッケージ。特定のドメインやタスクに対する「オンボーディングガイド」として機能する。

### スキルが提供するもの

1. **専門的なワークフロー** - 特定ドメイン向けの複数ステッププロセス
2. **ツール統合** - 特定のファイル形式やAPIとの連携方法
3. **ドメイン知識** - プロジェクト固有の知識、スキーマ、ビジネスロジック
4. **バンドルリソース** - スクリプト、リファレンス、アセット

## 基本原則

### 簡潔さが重要

コンテキストウィンドウは共有リソース。スキルはシステムプロンプト、会話履歴、他のスキルのメタデータ、ユーザーリクエストとコンテキストを共有する。

**デフォルトの前提: エージェントは既に十分賢い。**

- エージェントが知らない情報のみを追加する
- 各情報に対して「本当にこの説明が必要か？」を問う
- 冗長な説明より簡潔な例を優先する

### 自由度の設定

タスクの脆弱性と変動性に応じて具体性のレベルを調整：

| 自由度 | 形式 | 使用場面 |
|--------|------|----------|
| 高 | テキストベースの指示 | 複数のアプローチが有効、コンテキスト依存 |
| 中 | 擬似コード/パラメータ付きスクリプト | 推奨パターンはあるが変動許容 |
| 低 | 具体的なスクリプト、少パラメータ | 操作が脆弱、一貫性が重要 |

## スキルの構造

```
skill-name/
├── SKILL.md (必須)
│   ├── YAMLフロントマター (必須)
│   │   ├── name: スキル名
│   │   └── description: スキルの説明と使用タイミング
│   └── Markdownの本文 (必須)
└── バンドルリソース (任意)
    ├── scripts/   - 実行可能なコード
    ├── references/ - 参照ドキュメント
    └── assets/    - テンプレート、アイコン等
```

### SKILL.md の形式

```markdown
---
name: スキル名
description: スキルの説明。いつ使うべきかを含める。
---

# スキルタイトル

エージェントへの詳細な指示...
```

**フロントマター:**
- `name` (任意): 省略時はフォルダ名を使用
- `description` (必須): トリガー判定に使用される。何をするか、いつ使うかを明記

### バンドルリソース

#### scripts/
繰り返し書き直されるコードや、確定的な信頼性が必要な場合に使用。

#### references/
エージェントが作業中に参照すべきドキュメント。スキーマ、APIドキュメント、ドメイン知識など。

#### assets/
出力で使用されるファイル。テンプレート、画像、ボイラープレートコードなど。

## スキル作成プロセス

### ステップ1: 具体例の理解

スキルの使用パターンを具体的な例で理解する。

質問例：
- 「このスキルはどんな機能をサポートすべき？」
- 「使用例を教えて？」
- 「このスキルをトリガーする発言は？」

### ステップ2: 再利用可能なリソースの計画

各具体例を分析：
1. ゼロから実行する方法を考える
2. 繰り返し実行時に役立つスクリプト、リファレンス、アセットを特定

### ステップ3: スキルの初期化

新しいスキルディレクトリを作成：

```bash
mkdir -p .claude/skills/new-skill-name
```

基本的なSKILL.mdを作成：

```markdown
---
name: new-skill-name
description: スキルの説明...
---

# スキル名

## 概要
このスキルの目的...

## 使用方法
- ステップ1...
- ステップ2...
```

### ステップ4: スキルの編集

スキルを編集する際、別のエージェントインスタンスが使用することを意識する。

**含めるべき情報:**
- 手続き的知識
- ドメイン固有の詳細
- 再利用可能なアセット

**ガイドライン:**
- 命令形/不定形を使用
- 500行以内に収める
- 大きなスキルは分割する

### ステップ5: テストと反復

実際のタスクでスキルを使用し、改善点を特定して更新する。

## プログレッシブ・ディスクロージャ

スキルは3レベルの読み込みシステムを使用：

1. **メタデータ** (name + description) - 常にコンテキストに含まれる (~100語)
2. **SKILL.md本文** - スキルがトリガーされた時 (<5k語)
3. **バンドルリソース** - 必要に応じて

### パターン1: リファレンス付きハイレベルガイド

```markdown
# PDF処理

## クイックスタート
pdfplumberでテキスト抽出: [コード例]

## 高度な機能
- **フォーム入力**: [FORMS.md](FORMS.md) 参照
- **APIリファレンス**: [REFERENCE.md](REFERENCE.md) 参照
```

### パターン2: ドメイン別整理

```
bigquery-skill/
├── SKILL.md (概要とナビゲーション)
└── references/
    ├── finance.md
    ├── sales.md
    └── product.md
```

## このプロジェクト固有の注意点

このプロジェクト (k_maps) でスキルを作成する場合：

- **日本語で記述**: コメント、ドキュメントは日本語
- **CLAUDE.md と整合性を保つ**: プロジェクトの基本方針に従う
- **Flutter/Dart固有の知識**: モバイル開発のベストプラクティスを含める
- **クロスプラットフォーム対応**: Windows/Android両方を意識

## 作成時のチェックリスト

- [ ] フロントマターにname/descriptionがある
- [ ] descriptionに使用タイミングが明記されている
- [ ] 本文が500行以内
- [ ] 具体的な例が含まれている
- [ ] 曖昧な指示がない
- [ ] 不要なドキュメント（README.md等）を含めていない
