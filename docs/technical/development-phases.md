# 開発ステップ案 (MVPから段階的に)

## 1. MVP (Minimum Viable Product)

- ローカルでの新規プロジェクトフォルダ作成。
- プロジェクトフォルダのルートに配置された単一のGeoPackageファイルの読み込み・作成（点レイヤーのみ）。
- 地図上への点フィーチャ描画・属性（テキスト1つ）入力。
- GPSによる現在位置表示。
- `flutter_map` を用いた背景地図表示 (OpenStreetMapなど)。
- ローカルへのプロジェクト保存・読み込み。
- 基本的なレイヤー表示（GeoPackage内のレイヤーリスト）。

## 2. フェーズ2

- 線、領域フィーチャの描画機能追加（フリーハンド描画含む）。
- プロジェクトフォルダ内のサブフォルダを再帰的にスキャンし、複数のGeoPackageファイルを認識。
- フォルダ構造とGeoPackageファイルを反映した階層的なレイヤー/レイヤーグループ管理機能（表示、基本的な操作）。
- 基本的なGoogle Drive連携:
  - ローカルプロジェクトをGoogle Driveの新規フォルダへアップロードし、連携情報をメタデータに保存（初期連携設定）。
  - Google Drive上の既存プロジェクトフォルダをローカルへダウンロードして新規プロジェクトとして開始し、連携情報をメタデータに保存。
  - 手動での一方向同期（ローカル→Drive、Drive→ローカルのどちらかを選択、または最後に編集した方が優先などシンプルな競合解決）。

## 3. フェーズ3

- 高度な編集ツール（頂点編集、移動など）。
- 属性スキーマ対応、複数属性の編集。
- GPSトラッキング（軌跡記録）。
- プロジェクトメタデータ（`project_meta.json`）の読み書きの拡充。
- Google Drive同期機能の強化: 双方向同期、差分同期の検討、より高度な競合解決メカニズムの検討。

## 4. フェーズ4以降

- オフラインマップ対応 (`flutter_map`の機能を活用)。
- 計測ツール。
- UI/UXのさらなる洗練。
- Git連携の検討・実装。
- その他、ユーザーフィードバックに基づく改善。
